# The fetch-based, cookie-credentialed client is canonical; the Axios bearer-token client is dead

Two HTTP client layers exist: `src/shared/client.ts` (a small `fetch` wrapper, `credentials: 'include'`) which every real API call (`auth.api.ts`, all `src/api/**/*.api.ts`) goes through, and `src/shared/api.client.ts` (an Axios instance with a Bearer-token request interceptor and a `/auth/refresh`-on-401 retry loop) which nothing imports. `useAuthStore`'s `accessToken` field is populated from the login response but is only ever read as a truthy gate on the `whoami` query — never attached to a request. This matches the backend: `sophon-api` authenticates via a signed session cookie, not a bearer token (see its ADR 0001), so the Axios client's refresh flow has no server-side endpoint wired to make it work as designed.

**Decision**: build new API calls on `shared/client.ts` with `credentials: 'include'`, and treat `useAuthStore.accessToken` as a login-state flag, not a real token. Don't route work through `shared/api.client.ts` or try to "fix" its refresh flow in isolation — completing it would require a coordinated change on the backend (a real `/auth/refresh` endpoint and bearer-token-reading guards), which hasn't been decided. Either finish that migration deliberately on both repos, or delete the dead client — don't let it accrete partial usage.
